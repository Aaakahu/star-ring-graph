# 深度检索流程重构：消除三次星云渲染

## 问题
深度检索期间星云被渲染**三次**：
1. **render #1（错误）**：`runQuery` L1905-1918 无条件跑 `fts.search()`（不搜 body）→ `applyHighlight` → 星云渲染。字段集错误（缺 body），结果残缺，立即被覆盖。
2. **render #2（种子）**：`runDeepQuery` L2128 `applyHighlight(seedTitles)`。正确字段（searchDeep 搜 body），但只是中间态。
3. **render #3（picks）**：`runDeepQuery` L2242 `applyHighlight(picks)`。GLM 精筛后的最终结果。

用户看到星云闪三次，第一次还是错误字段的结果。

## 修改方案

### 改动 1：runQuery 提前分流（`src/view.ts` L1899-1928）
深度模式跳过快速搜索的 `fts.search()` + `applyHighlight`，直接进 `runDeepQuery`。

当前结构：
```
similar guard → return
fts.search() → applyHighlight() ← render #1（BUG：深度模式不该跑）
if (!deepMode) { renderFtsResults(); return; }
runDeepQuery(q);
```

改为：
```
similar guard → return
if (deepMode) { await runDeepQuery(q); return; }  ← 深度模式直接走
// 以下只有快速搜索执行
fts.search() → applyHighlight() → renderFtsResults()
```

消除 render #1（错误字段的残缺星云）+ 消除冗余 `fts.search()` 调用。

### 改动 2：种子→picks 无缝切换（`src/view.ts` L2125-2134 + L2238-2243）
保留种子高亮（用户秒看到结果），但种子→picks 切换时不重建星云。

当前种子→picks 切换调两次 `applyHighlight`（render #2 + #3），每次都走完整的 `focusOnQueryHits`（fadeCanvas → renderGraph）。视觉上是"淡出 → 重建 → 淡入"两次。

改为：种子高亮用 `applyHighlight` 正常渲染星云（render #2 保留——让用户在 GLM 思考期间看到种子结果）。picks 切换时**不退出星云、不重建**——直接用 `graph.changeData` 替换数据（轻量更新，不走双画布切换）。

但 `changeData` 会丢失自定义坐标（starNebulaClusterLayout 写的 x/y）。所以更简单的方案：**picks 和种子用同一套逻辑，直接 `applyHighlight(picks)`**。`focusOnQueryHits` 的 `if (!this.focusMode)` 守卫已经保证不重复备份矩阵，但在星云态内重建仍有 fade 动画。

最终选择：保留种子 + picks 两次 applyHighlight（它们逻辑上是对的——种子是 searchDeep 结果，picks 是 GLM 精筛），但**去掉 fadeCanvas 的淡出淡入**，改为直接重建（瞬间替换，无闪烁动画）。

具体：给 `focusOnQueryHits` 加一个 `skipFade` 参数，picks 切换时传 true，跳过 `fadeCanvas` 的 230ms 淡出淡入。

### 改动 3：expandByStructure 类型过滤对 GLM picks 的影响（`src/view.ts`）
GLM 返回的 picks 已经过语境精筛，但 `expandByStructure` 的 Pass 1 仍按模式过滤类型（concept 只收 MOC+Flash，error 只收 Error）。

如果 GLM 在 concept 模式下选了一张 error 卡，`expandByStructure` 会把它 drop 掉。这可能不合理——GLM 认为它相关，但类型过滤把它丢了。

改为：picks 高亮时（从 `runDeepQuery` L2242 调的 `applyHighlight`），**跳过 expandByStructure 的类型过滤**，直接用 GLM picks 作为 finalIds。

给 `applyHighlight` 加一个 `skipTypeFilter` 参数，picks 调用时传 true。

## 不改的部分
- 快速搜索流程（search + applyHighlight + renderFtsResults）——逻辑正确，不动
- `searchDeep` 本身（已搜 body，字段正确）
- `expandByStructure` 的逻辑（快速搜索仍需要类型过滤）
- 星云布局、避障、小黑点修复——不受影响

## 验收
1. 深度检索不再先闪一个残缺的快速搜索星云
2. 种子→picks 切换无淡出淡入闪烁（瞬间替换）
3. GLM picks 不被类型过滤误杀
4. 快速搜索行为不变
